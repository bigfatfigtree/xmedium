# Extra Medium — xmedium.co rebuild (Oct 2026)

Static site, no build step (Netlify publish = "."). Pages are generated by `build.py`:
edit content in `build.py`, run `python3 build.py`, commit everything.

## Structure
- `/` — homepage: studio positioning, SIGNL flagship panel, proof-led work, four offers, founder
- `/work/` — case stories (anonymized, outcome-led) + SIGNL flagship callout
- `/services/` — the studio: Launch / Reinvent / Grow / Lead / Intelligence / Experiences + 3 engagement shapes
- `/labs/` — Extra Medium Labs: SIGNL flagship, ventures bench (Roon, JAWNRA, hapsta), rest archived
- `/labs/signl/` — SIGNL flagship case study (problem, what we built, how a visit works)
- `/about/` — Jeff + principles
- `/contact/` — Netlify form (name "contact") + hello@xmedium.co
- `_redirects` — all legacy URLs from the old 41-page site 301 to the new structure

## Deploy (one-time setup, Jeff)
The old site's source was never in GitHub, so this repo is new.
1. Jeff creates an empty GitHub repo named `xmedium` under bigfatfigtree (repo creation via token fails — known limitation).
2. Muse pushes this repo to it.
3. In the EXISTING Netlify site for xmedium.co: Site configuration → Build & deploy → Continuous deployment → Link an existing site to a Git repository → pick bigfatfigtree/xmedium (publish dir ".", no build command). Domain/DNS untouched.
   Alternative if linking fights: Netlify → Add new site → Import from Git → same repo, then move the xmedium.co domain to the new site.
4. Muse verifies the live deploy (homepage + /labs/signl/ + one legacy redirect).

Contact form needs Netlify Forms detection on first deploy (form name "contact" is in /contact/).
